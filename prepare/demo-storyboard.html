AsyncPair — 데모 영상 스토리보드

목표 길이 ~3분 · 나레이션 영어 · 화면 녹화 + 보이스오버 · IBM Bob Hackathon
한 줄 스토리. 보스턴에서 만나 함께 해커톤을 다니던 두 개발자가 13시간 시차로 갈라졌다. AsyncPair는 그 시차 너머로 페어 프로그래밍을 잇는다 — 커밋 순간 핸드오프를 포착하고, 팀원이 자는 동안 AI가 그를 대신한다.
나레이션 언어 — 국제 해커톤(IBM/lablab.ai) 심사라 영어로 작성했습니다. 각 씬의 노란 박스가 보이스오버 대본입니다. 한국어로 갈 거면 아래 회색 줄을 참고해 바꾸세요.

🎬 촬영 준비 (녹화 시작 전)

  1. git pull — ibm-bob-hackathon-main 최신으로.
  2. rm -rf .asyncpair — 앱이 data/seed.json에서 데모 핸드오프를 새로 로드하도록 (이게 화면에 나올 데이터).
  3. npm run build:cli 그리고 npm link — 터미널에서 asyncpair 명령이 바로 되게.
  4. 터미널 A: npm run dev → localhost:3000 띄워두기. (.env의 GEMINI_API_KEY를 Next.js가 자동으로 읽어 → /pairing에서 실 Gemini 작동.)
  5. 터미널 B: 깨끗한 화면 하나 — Scene 3의 CLI 시연용. 글자 크게(16pt+), 다크 테마.
  6. 브라우저 — 주소창·북마크바 정리, 줌 100%, 시크릿 창 권장.
씬은 한 번에 이어 찍을 필요 없음 — 터미널 씬과 브라우저 씬을 따로 찍어 편집으로 붙이면 됩니다. 나레이션이 다리 역할.
데모 데이터 — 화면에서 검토할 핸드오프(보스턴 → 서울, "notifications" 작업)는 data/seed.json에 미리 넣어둔 연출용 데모 데이터입니다. Scene 3의 capture는 "포착이 이렇게 일어난다"를 보여주는 실제 시연이고, Scene 4에서 검토하는 건 이 시드 핸드오프예요.

🎙️ 전체 나레이션 (이어 읽기용)

S1 Two years ago, in Boston, we met at a hackathon. We kept showing up — ten hackathons, side by side, one laptop next to another. Then last week, my teammate flew home to Korea. Now thirteen hours sit between us. When I'm coding, he's asleep. When he's coding, I'm asleep. But we still want to build together — so we built a way to.

S2 Async collaboration sounds easy — until you try it. A git commit tells you what changed, never why. A question sent at midnight waits a full day for an answer. The handoff itself becomes the bottleneck.

S3 This is AsyncPair. I've just finished my session in Boston. Instead of writing a long handoff doc, I run one command — asyncpair capture. It reads my git activity automatically, and asks me two quick questions while everything is still fresh. Twenty seconds. It becomes a structured handoff — then I push, and log off.

S4 Thirteen hours later, my teammate wakes up in Seoul. The handoff is already waiting — what I did, what's still unfinished, and the exact situations he's most likely to run into, each with a suggested approach. He accepts it, and starts not from zero, but from where I stopped.

S5 Then he hits something the notes didn't cover. Normally, that's a lost day. Instead, he asks the AI stand-in. It answers with my context — my commits, my decisions, my reasoning — the way I would have. He stays unblocked. The pair never breaks, even though one of us is always asleep.

S6 This isn't just our story. It's every team split across time zones. Every developer with a different rhythm — early risers, night owls, parents, remote teammates half a world apart. They've all been told real collaboration needs a shared clock. It doesn't.

S7 AsyncPair. Async pair programming, across any distance. Built with IBM Bob.

📌 촬영 팁

  • 속도 — 클릭 사이를 충분히 쉬어 나레이션이 따라오게. 편집에서 줄이긴 쉬워도 늘리긴 어렵다.
  • 커서 — 클릭할 버튼으로 천천히, 분명하게 이동. 시청자가 눈으로 따라올 수 있게.
  • S1·S6의 감정 — 천천히, 진심으로. S3~S5의 데모는 또렷하고 자신감 있게.
  • 스탠드인 답변(S5)은 라이브라 몇 초 걸린다 — 로딩 점을 그대로 보여주면 "진짜 AI"라는 신호.
  • 화면 해상도 — 1080p 이상, 브라우저 줌 100~110%, 글씨가 영상에서 읽히게.
  • 음악 — 잔잔한 배경음 한 겹. S6에서 살짝 차오르게.
  • 제출 영상은 보통 2~4분 — 이 구성은 ~3분. 길면 S2·S6를 먼저 줄인다.
