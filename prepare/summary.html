핵심 Q&A

Q. Bobcoin이 뭐임?

해커톤 동안 IBM Bob을 쓸 수 있는 사용량 크레딧입니다 (공지에선 "BP Coins"라고도 부름 Discord).

  • 계정당 40개 지급 = 팀원 1인당 40개. 팀이면 총 40×인원. 가이드 p6
  • Bob AI와 상호작용할 때마다 차감. 가이드 예시: 작은 작업 1개 ≈ API Cost 0.52 Bobcoin. 가이드 p6가이드 p19
  • 100% 소진 시 추가 지급 없음. 그 후에도 작업·제출은 가능하고 watsonx를 fallback으로 안내. 가이드 p6
  • 다 쓰면 work를 export 못 할 수 있음. Discord
  • 잔액 확인: Bob IDE → Settings → General → Budget / Usage. 가이드 p7

→ 무거운 자동 실행(Plan+Code)은 코인을 빨리 먹음. 계획적으로 쓸 것. 분석

Q. 우리가 만드는 게 "개발을 빠르게 하는 도구"야?

챌린지 제목은 "Turn idea into impact faster", 헤드라인은 "Build solutions that improve how software is built(소프트웨어를 만드는 방식을 개선하라)"입니다. 이벤트가이드 p4 챌린지가 든 예시도 전부 개발 생산성 쪽 — 기존 코드 빠르게 파악 / 문서·테스트 생성 / 반복작업 감축. 이벤트가이드 p4

해석 주의 분석: "반드시 개발자 도구여야 한다"고 못박은 규정은 없습니다. 해석이 둘로 갈림 —

  • A (우리 권장) — 만드는 제품 자체가 개발자 생산성 도구
  • B — 아무거나 만들되 Bob을 개발에 썼다는 걸 보여줌 (실제 제출작 목록에 일반 앱도 있음 이벤트)

A를 권장하는 건 우리 판단 분석: 챌린지 예시가 전부 개발 생산성이고, 그래야 Bob을 무겁고 눈에 띄게 쓰게 되어 세션 리포트 기반 심사에 유리하기 때문.

Q. Bob을 활용해서 앱을 만드는 거야, Bob을 활용하는 앱을 만드는 거야?

두 축을 구분 분석: 축 1 = Bob을 개발 도구로 씀 (Bob IDE로 우리 앱을 만든다) · 축 2 = Bob을 앱 속 부품으로 내장.

해커톤이 요구하는 건 축 1. 가이드가 "솔루션은 Bob IDE를 core component로 showcase해야 한다"고 명시 가이드 p4, 필수 제출물인 세션 리포트가 곧 "Bob IDE로 짰다"는 증거 가이드 p4가이드 p18. 축 2가 요구사항이 아니라는 건 우리 해석 분석 — Bob IDE는 데스크톱 IDE라 앱이 코드로 호출하는 API가 아님.

→ 우리 앱의 AI 기능은 watsonx.ai 등 LLM이 담당. 제품이 Bob을 내장할 필요는 없음. 분석

Q. Bob IDE를 꼭 써야 해?

네. 가이드가 "You must use Bob IDE for this hackathon"이라 명시하고, 심사 자격을 위해 Bob IDE를 core component로 showcase해야 합니다. 가이드 p4가이드 p8 심사는 Bob IDE에서 export한 세션 리포트를 근거로 함. Bob Shell은 선택. 가이드 p8

Q. 데모는 어디에 배포해?

해커톤 제공 IBM Cloud 계정은 solution deployment를 지원하지 않음 — 로컬에서 실행해 보여주라고 가이드가 안내. 가이드 p44 제출 시 데모 플랫폼·라이브 URL을 요구하므로 가이드라인 자체 호스팅(Vercel 등)을 쓰면 됨 분석.

Q. 세션 리포트가 뭐고 왜 중요해?

Bob IDE 작업 기록을 markdown으로 export한 것 + 소비 요약 스크린샷. 팀원 각자가 export해 리포 bob_sessions/ 폴더에 올려야 하며, 이게 심사 근거입니다. 가이드 p18가이드 p19 (절차는 "세션 & 보안" 탭)

Q. Claude Code 같은 다른 도구를 같이 써도 돼?

가이드 명시: "어떤 프레임워크·기술이든 사용 가능 — 단 솔루션이 Bob IDE를 core component로 showcase해야 함." 가이드 p4 다른 AI 도구 병행을 금지하는 조항은 없음.

핵심 빌드는 Bob IDE에서 하고 다른 도구는 보조로만 — 이건 우리 전략 분석. Claude Code는 해커톤이 제공하지 않으니 본인 계정 필요. (자세히는 "셋업" 탭)

전략 5원칙 분석

  1. 심사 = Bob 세션 리포트. 그냥 코딩하면 안 됨 — Bob에게 실제로 많이, 의미 있게 시키고 그 과정이 리포트에 남아야 점수가 나옴.
  2. 메타 시너지. 챌린지가 "개발을 더 빠르게"라서, 프로젝트 자체가 개발자 도구면 시너지가 생겨 독창성·기술적용에 유리.
  3. Bobcoin 40개는 예산. 초반 탕진 금지. 무거운 작업에 집중 투입하고 잡일은 직접.
  4. 48시간 = 작게. 데모 가능한 기능 1개 완성이 미완성 기능 5개보다 훨씬 높은 점수.
  5. 제출물을 미루지 말 것. 영상·슬라이드·세션 리포트 export를 마지막에 몰면 망함.

도구 분담 — Bob vs Claude Code 분석

원칙: "풍부한 세션"은 연출이 아니라 Bob이 실제로 의미 있는 일을 많이 한 결과. 심사위원은 속 빈 세션을 바로 알아봄.

💡 발상 전환 — Bob 사용은 비용이 아니라 연료 우리 제품이 bob_session을 입력으로 먹음 → Bob을 진짜로 많이 쓰면 풍부한 세션 = 제출 요건 + 제품 데모 데이터. 일석이조.

Bob 세션을 정당하게 풍부하게

  • Plan mode → Code mode 순서 — 분석+계획 다음 구현 = 자연히 멀티스텝
  • 한 줄 질문 말고 기능/모듈 단위로 통째 맡기기
  • 잘게 100개로 쪼개지 말 것 — 기능당 응집된 세션 1개
  • 팀원 각자 의미 있는 Bob task 분담 (각자 export 필수 가이드 p18)

Bobcoin 현실

40×2 = 80 Bobcoin (40/계정 가이드 p6). 작은 task ≈ 0.52코인 가이드 p19 → 코어를 다 Bob으로 해도 넉넉하다는 게 우리 추정 분석.

📌 지금 당장

IBM Bob & Bob IDE 가이드 p2가이드 p8

IBM Bob은 코드베이스와 직접 작업하는 AI 개발 파트너. 전체 리포지토리 컨텍스트를 갖고 의도를 이해하고, 로직을 설명하고, 복잡한 변환을 자동화하고, 다단계 작업을 정리해줌.

두 가지 작업 방식 가이드 p8

  • Bob IDE — 필수. 반드시 사용; 세션 리포트를 여기서 export.
  • Bob Shell — 선택. 커맨드라인용, 자동화에 유용.

Bob IDE 주요 기능 가이드 p10–15

  • 채팅 인터페이스 / Modes (Plan · Code · Advanced · Ask · Orchestrator) / Custom modes
  • Auto-approve / Custom instructions / Skills (재사용 가능한 작업 레시피)
  • MCP 서버 / Context mentions(@) / Literate coding
  • Bob tips(실시간 품질 진단) / Code actions / Next Edit
  • Slash commands (/init → AGENTS.md, /create-pr, /review)
  • Checkpoints / Code reviews / Commit messages / Pull requests / Enhance prompt

Bob 세션 리포트 export (심사 필수) 가이드 p18–19

팀원 각자가 관련된 모든 Bob task 세션 리포트를 export해서 최종 리포지토리에 업로드해야 함.

  1. 리포에 bob_sessions/ 폴더 생성.
  2. Bob IDE 채팅 → Views and More Actions → History.
  3. 올바른 workspace 확인 (여러 개면 All 선택).
  4. 작업 열기 → task 헤더 선택 → 세션 소비 요약 표시.
  5. 소비 요약 스크린샷 찍기.
  6. Export task history 선택 → task 기록을 markdown으로 다운로드.
  7. 제출 관련 모든 작업에 대해 반복.
  8. 스크린샷 + markdown 파일 전부 bob_sessions/에 업로드.
⛔ export 전에 가이드 p18 코드에서 모든 크리덴셜·API 키 제거. public 리포에서 IBM Bob/Cloud 크리덴셜이 발견되면 IBM 보안팀이 계정 접근을 비활성화함.
