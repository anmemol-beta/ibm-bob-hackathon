IBM Bob & Bob IDE

IBM Bob is an AI-powered development partner that works directly with the codebase with full repository context — it understands intent, reads complete repo context, explains logic, automates complex transformations, and streamlines multi-step work.

Two ways to work

  • Bob IDE — Required. Must be used; session reports are exported from it.
  • Bob Shell — Optional. Brings Bob to the command line for automation.

Exporting Bob Session Reports (required for judging)

Each team member must export and upload all relevant Bob task session reports into the final code repository.

  1. Create a folder named bob_sessions/ in the project repo.
  2. Bob IDE chat → Views and More Actions → History.
  3. Confirm the correct workspace (or select All for multiple workspaces).
  4. Open a task → select the task header → the task session consumption summary appears.
  5. Take a screenshot of the consumption summary.
  6. Select Export task history → downloads the task history as a markdown file.
  7. Repeat for every task related to the submission.
  8. Upload all screenshots + exported markdown files into bob_sessions/.
⛔ Before exporting Remove all credentials and API keys from the code. If IBM Bob or Cloud credentials are detected in the public repo, the IBM Security team will deactivate account access.

Security & Data Rules

  • Never expose API keys / credentials in the repo — IBM security scanners run 24/7 and will immediately deactivate access; the cloud account stays suspended until the key is removed everywhere, rotated, and remediation is confirmed with support.
  • Keep the GitHub repository public.

Data set rules (bring your own data)

  • Teams are responsible for data compliance.
  • Public-website data is allowed only if terms permit commercial use — keep a list of sources.
  • Not allowed: company-confidential data, client data, personal information (PI), social-media data.
