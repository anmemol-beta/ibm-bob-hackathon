핵심 Q&A

Q. Bobcoin이 뭐임?

해커톤 동안 IBM Bob을 쓸 수 있는 사용량 크레딧입니다 (공지에선 "BP Coins"라고도 부름).

  • 계정당 40개 지급 = 팀원 1인당 40개. 팀이면 총 40×인원.
  • Bob AI와 상호작용할 때마다 차감. 가이드 예시: 작은 작업 1개 ≈ API Cost 0.52 Bobcoin.
  • 100% 소진 시 추가 지급 없음. 단 그 후에도 작업·제출은 가능하고 watsonx를 fallback으로 안내.
  • 잔액 확인: Bob IDE → Settings → General → Budget / Usage.

→ 무거운 자동 실행(Plan+Code)은 코인을 빨리 먹음. 다 쓰면 export가 막혀 제출이 위험해질 수 있으니 계획적으로.

Q. 우리가 만드는 게 "개발을 빠르게 하는 도구"야?

원칙적으로 그렇습니다. 챌린지 제목이 "Turn idea into impact faster", 헤드라인이 "개발 방식 자체를 개선하라"입니다. 해석이 둘로 갈립니다:

  • A (권장) — 만드는 제품 자체가 개발자 생산성 도구
  • B — 아무거나 만들되, Bob을 개발에 썼다는 걸 보여줌 (실제 제출작 중에도 일반 앱 존재)

A를 권장: 챌린지가 명시적으로 개발자 도구를 요구하고, Bob을 무겁고 눈에 띄게 쓰게 되어 심사(세션 리포트 기반)에 유리.

Q. Bob IDE를 꼭 써야 해?

네. Bob IDE는 필수이고 심사 자격 조건입니다. 심사는 Bob IDE에서 export한 세션 리포트를 근거로 합니다. Bob Shell은 선택.

Q. 데모는 어디에 배포해?

해커톤용 IBM Cloud 계정은 배포를 지원하지 않음. 데모는 로컬에서 실행하거나 자체 호스팅(Vercel 등)에 올린 뒤 제출에 보여줘야 합니다.

Q. 세션 리포트가 뭐고 왜 중요해?

Bob IDE에서 한 작업 기록을 markdown + 소비 요약 스크린샷으로 export한 것. 팀원 각자가 export해서 리포 bob_sessions/ 폴더에 올려야 하며, 이게 곧 심사 근거입니다. (자세한 절차는 "세션 & 보안" 탭)

Q. Claude Code 같은 다른 도구를 같이 써도 돼?

됩니다. 가이드는 "어떤 프레임워크·기술이든 사용 가능 — 단 솔루션이 Bob IDE를 core component로 showcase해야 함"이라고 명시. 다른 AI 도구 병행을 금지하지 않습니다.

다만 심사 근거가 Bob 세션 리포트이므로 핵심·의미 있는 빌드는 Bob IDE에서 하고 다른 도구는 보조(리서치·슬라이드·주변 스크립트)로만. Bob을 의미 있게 안 쓰면 실격 위험. Claude Code는 해커톤이 제공하지 않으니 본인 계정 필요. (자세히는 "셋업" 탭)

이 탭은 대화 진행에 따라 계속 업데이트됩니다.

전략 5원칙

  1. 심사 = Bob 세션 리포트. 그냥 코딩하면 안 됨 — Bob에게 실제로 많이, 의미 있게 시키고 그 과정이 리포트에 남아야 점수가 나옴.
  2. 메타 시너지. 챌린지가 "개발을 더 빠르게"라서, 프로젝트 자체가 개발자 도구면 "Bob으로 개발자 도구를 만든다"는 시너지가 생겨 독창성·기술적용에 유리.
  3. Bobcoin 40개는 예산. 초반 탕진 금지. 무거운 변환·생성 작업에 집중 투입하고 잡일은 직접.
  4. 48시간 = 작게. 데모 가능한 기능 1개 완성이 미완성 기능 5개보다 훨씬 높은 점수.
  5. 제출물을 미루지 말 것. 영상·슬라이드·세션 리포트 export를 마지막에 몰면 망함.

IBM Bob & Bob IDE

IBM Bob은 코드베이스와 직접 작업하는 AI 개발 파트너. 전체 리포지토리 컨텍스트를 갖고 의도를 이해하고, 로직을 설명하고, 복잡한 변환을 자동화하고, 다단계 작업을 정리해줌.

두 가지 작업 방식

  • Bob IDE — 필수. 반드시 사용; 세션 리포트를 여기서 export.
  • Bob Shell — 선택. 커맨드라인용, 자동화에 유용.

Bob IDE 주요 기능 (활용 가능한 부품)

  • 채팅 인터페이스 / Modes (Plan · Code · Advanced · Ask · Orchestrator) / Custom modes
  • Auto-approve / Custom instructions / Skills (재사용 가능한 작업 레시피)
  • MCP 서버 / Context mentions(@) / Literate coding
  • Bob tips(실시간 품질 진단) / Code actions / Next Edit
  • Slash commands (/init → AGENTS.md, /create-pr, /review)
  • Checkpoints / Code reviews / Commit messages / Pull requests / Enhance prompt

Bob 세션 리포트 export (심사 필수)

팀원 각자가 관련된 모든 Bob task 세션 리포트를 export해서 최종 리포지토리에 업로드해야 함.

  1. 리포에 bob_sessions/ 폴더 생성.
  2. Bob IDE 채팅 → Views and More Actions → History.
  3. 올바른 workspace 확인 (여러 개면 All 선택).
  4. 작업 열기 → task 헤더 선택 → 세션 소비 요약 표시.
  5. 소비 요약 스크린샷 찍기.
  6. Export task history 선택 → task 기록을 markdown으로 다운로드.
  7. 제출 관련 모든 작업에 대해 반복.
  8. 스크린샷 + markdown 파일 전부 bob_sessions/에 업로드.
⛔ export 전에 코드에서 모든 크리덴셜·API 키 제거. public 리포에서 IBM Bob/Cloud 크리덴셜이 발견되면 IBM 보안팀이 계정 접근을 비활성화함.
